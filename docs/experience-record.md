# 경험 기록: quiz-validator (AI 생성 문항 문체 검증기)

- 계열: 없음
- 기간: 2026-05 (커밋 2026-05-13 최초 공개, 2026-06-07 학습 가이드 추가)
- 인원·구성: 개인(커밋 작성자 1인 계정 + 가이드 커밋 1건)
- 본인 역할: 규칙 설계, 앵커 보정(calibration), CLI 구현 전반(레포 단독 작성으로 보임, 확정은 미확인)
- 성격: 개인 도구 프로젝트, 실사용자 수 미확인
- 최종 갱신: 2026-11-23

## 1. 상황과 판돈
- 무엇 때문에 시작했나: LLM이 만든 객관식 문항이 "Which of the following BEST..." 같은 같은 문체·어휘를 반복해 AI가 썼다는 티가 난다. 출제 전에 걸러낼 검증기가 필요했다(README Why this exists).
- 왜 중요했나: 문항 품질 저하. 판돈은 개인 문항 생성 작업의 품질. 외부 기대는 미확인.
- 그때의 제약: 모델·학습데이터 없이 규칙만 사용, 보정 기준은 AWS가 공개한 SAA-C03 샘플 10문항.

## 3. 판단
- 정한 것: ML 분류기 대신 투명한 정규식·통계 규칙으로 구현. 도메인 설정을 JSON으로 분리해 PMP·CFA 등으로 확장 가능하게 함.
- 정한 사람: 본인(README 서술 기준).
- 버린 선택지: ML 기반 탐지(README는 장점으로 투명성·속도·모델 비의존을 들어 배제 사유를 적음).
- 판단 근거: 공식 샘플 10/10이 HARD 통과, 평균 품질 점수 8/100 → 공식 샘플은 깨끗하나 밋밋하다는 관찰.

## 4. 결과와 상대의 변화
- 확인된 결과: HARD 규칙 통과율 10/10, 평균 품질 점수 8/100(공식 샘플 10문항 기준, README 기재). 직접 재실행은 하지 않음.
- 수치: 표본 10문항 한정. 생성 문항이 80점 이상을 받을 수 있다는 서술은 README 주장이며 측정 로그는 미확인.
- 상대의 변화: 해당 없음.
- 안 된 것·남은 문제: 규칙이 공개돼 있어 우회 가능, 더 깊은 LLM 특성은 못 잡는다고 README가 스스로 한계로 적음.
